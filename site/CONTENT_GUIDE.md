# Writing docs pages (for every contributor, human or agent)

Site: Astro + Starlight in `site/`. Pages live in `src/content/docs/<section>/<slug>.mdx`, URL `/<section>/<slug>/`.
Sections: start, concepts, strategies, integrations, guides, migration, reference. (The `api/` folder is generated by TypeDoc — never edit it.)
Source of truth: the library in `../src/*.ts` (read it!), `../README.md`, `../examples/*.ts`, and the tests in `../test/*.test.ts`
(tests show exact, verified behaviour). Never document something you didn't verify in the source.

## Audience and tone
Engineers integrating the library. Short, concrete, code-first. Lead with what it's for and when to use it, then code.
No marketing fluff, no "simply", no emoji in prose. English. Sentences short. Explain *why* behind defaults.

## Code blocks
- Use ```` ```ts twoslash ```` for TypeScript examples that import the library: they are TYPE-CHECKED at build time
  against the real source (`'resilience-pipeline'` and subpaths like `'resilience-pipeline/fetch'` resolve to `../src`).
  A type error fails the build — so examples must compile. Declare external things you use but don't define:
  `declare function fetchUser(id: string): Promise<User>;` (put scaffolding above `// ---cut---` to hide it).
- Show types on hover with `//    ^?` sparingly (one per page max), only where the inferred type is the point (typed errors).
- Use plain ```` ```ts ```` (no twoslash) only for snippets that can't compile standalone (framework apps needing packages
  not installed in `site/` — e.g. Express/Fastify/Nest/ioredis/axios snippets).
- Shell: ```` ```sh ````. Titles: ```` ```ts title="payments.ts" ````. Highlight lines: `{3-5}`.

## Strategy page template (strategies/*)
1. One-paragraph "what & when" (what failure it handles; when NOT to use it).
2. Minimal example (twoslash), both `addX()` and `xStrategy()` forms in `<Tabs>` when relevant.
3. "How it works" (state machine / timeline in prose or a small table).
4. Options table: `| Option | Type | Default | Description |` — every option, defaults from the source.
5. Events (telemetry names + callback names) and errors it raises (class + `code` + HTTP mapping).
6. Recipes / common mistakes (Aside).
7. "Related" links.

## Links
Internal links are absolute without domain: `/strategies/retry/`, `/concepts/typed-errors/`. API reference pages live under
`/api/<entry>/...` (e.g. `/api/index/classes/resiliencepipelinebuilder/`). Only link pages that exist or are in the plan
(see PLAN.md); the build validates links.

## Building while others build (IMPORTANT)
Several people/agents build at the same time. Always build into your own folders and skip the API generation:
```sh
cd site && SKIP_TYPEDOC=1 ASTRO_OUT_DIR=/tmp/rp-site-<yourname>/dist ASTRO_CACHE_DIR=/tmp/rp-site-<yourname>/cache npx astro build
```
(Use the scratchpad dir you were given instead of /tmp if one is provided.) The build type-checks every `twoslash` block and validates
internal links (links into `/api/**` are not checked in this mode). It must end with `Complete!`.
While other sections are still being written, add `SKIP_LINKS=1` too (links to pages that don't exist yet would fail);
the full link check runs at the end.
